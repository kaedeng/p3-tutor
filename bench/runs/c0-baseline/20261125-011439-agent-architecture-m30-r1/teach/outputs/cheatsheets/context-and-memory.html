Context and memory

The model works from its training plus what is in its context. Everything else must be brought in.

Where information lives

KindLives inUse for
Fixed contextSent every callRules, tool definitions
Message historyProgram's list, resent each callQuestion, tool requests, results
Saved notesFile or database; must be loadedStable preferences, current project
Live lookupOfficial system, via a toolFree slots, training status
RetrievalChunked manuals, searchedThe few relevant passages

What fills the context window

System prompt, tool definitions, all messages and results, and the reply being written.

Input cost of one request

Add the input of every call: each call contains the earlier history again (when nothing is removed). Then multiply by the price per token. Output is billed on top. Caching can lower the price, not the space used.

Rough size: about 3.5 English characters per token on one provider's newer models.

When the context grows

TechniqueDoesRisk
TrimDrop oldest messagesLose early requirements
Clear tool resultsRemove used raw resultsMust fetch again
CompactSummarize and continueSummary loses detail

Retrieval steps

  1. Split documents into chunks; label each with machine, section and page.
  2. Search by keywords, by meaning (embeddings), or both.
  3. Put the top few chunks into the context.

Note rules (design suggestions)

Save what is stable and useful. Date it. Let the student fix or delete it. Never save secrets. Take the student's identity from the login.
