Context and memory

The model knows its training plus what is in this call's input. Anything else must be put there.

Where information lives

PlaceLastsHolds
Context windowOne model callSystem prompt, tool definitions, messages, tool results, documents, and the reply
Short-term memoryOne session (thread)Message history your program keeps and resends
Long-term memoryAcross sessionsSaved notes: facts, past events, rules
Document indexUntil you rebuild or change itManual chunks to search

Cost of a request

For each call: input tokens × input price + output tokens × output price. Add up every call. Resent text is paid for again; caching can lower its price.

When history grows

TrimDrop old messages. Risk: losing a requirement.
Clear resultsRemove bulky tool output, keep a pointer. Risk: refetching.
CompactSummarize and continue. Keep goal, facts, unfinished work, open questions.

Finding manual pages

Keyword (BM25)Exact terms: part numbers, error codes
EmbeddingsRelated meaning in different words
ChunksKeep manual name and section heading with each
Small collectionSending it all may work; check cost and answer quality first

Five questions for any request

  1. What is always sent?
  2. What is loaded from memory?
  3. What is retrieved or looked up?
  4. What stays out?
  5. What is saved afterwards?

Design rules of thumb: date saved notes; keep students' notes separate; check safety and access facts at their official source.
